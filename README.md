> **一句文字，生成可烧录的 STM32 工程** —— 不用手配 CubeMX，不用手建 MDK 工程。
> 主线是**确定性代码生成骨架**：文字 → 识别套式 → 模板锻造 → 106 条校验 → 真编译，
> **不强制依赖 LLM**（LLM 作为可选兜底，可剥离）。

这是一副**能开的空车**：骨架（编排 + 校验 + 编译链路 + 契约接口）全交出去，血肉（芯片肖像 / 功能模板 / 手册数据）留在原项目，每个血肉格子贴了「格式标签 + 空模板」。你 clone 下来照着标签填自己的肉，就能跑起来——**内容是私有的，格式是大家的**。

## 定位（先读这段）

> **V1.0 · 初版框架，不是拿来即用的成品。**
>
> 这是一个**成长性项目**。它给你的底子是「确定性代码生成骨架」——识别套式 → 模板锻造 → 106 条校验 → 真编译，主线不强制依赖 LLM。这是**作者保证的下限**：能跑通、不出错。
>
> 它的**上限取决于你**。芯片肖像、功能模板、手册数据这些「内容」不开源，需要你自己填肉。更关键的是**连接能力**：项目给的是最底层的原子（一个外设一个模板，铺开、逐个贴）+ 最朴素的思路（要分层、要隔离，不要堆一起）。把「点灯」改成「外设 + 引脚 + 按键」，或像看门狗那样把「启动 + 观察 + 重置」串成一条链、再用一个词代替——**这是你拼出来的，不是项目自带的**。这就是二创，就是成长：我保证下限，上限取决于你。

## 核心特性

| 特性 | 说明 |
|---|---|
| 🎯 **确定性优先** | 识别 → 模板锻造 → 106 校验 → 真编译，主线不强制依赖 LLM，同一输入同一输出 |
| 🧩 **材料驱动** | 芯片肖像 / 功能模板 / 手册全是 JSON、YAML，加能力 = 加材料，不改骨架 |
| 🔒 **106 条校验** | 19 类外设的工艺标准，拦截引脚冲突、时钟顺序、喂狗位置等错误 |
| 🛠️ **真编译** | arm-none-eabi-gcc 真编译，编译不过就是错——不是「看起来对」 |
| 🏗️ **开发板 / 芯片并列** | 板载定型引脚 vs 芯片默认引脚，井水不犯河水，谁也别覆盖谁 |
| 🔗 **连接能力** | 原子 + 分层思路，把「点灯」拼成「外设 + 引脚 + 按键」，就是二创 |

## 为什么不是「纯 LLM 生成」

| 维度 | 纯 LLM 生成 | 本骨架 |
|---|---|---|
| **确定性** | 每次可能不一样 | 同一输入，同一输出 |
| **可验证** | 黑盒，靠猜 | 106 条校验 + 真编译 |
| **引脚正确性** | 大概率错、上板露馅 | 材料化标准值，上板验过 |
| **复杂外设** | 容易报废、修个没完 | 模板锻造，可复现 |
| **可托付** | 你敢让它上板吗 | 编译过 ≠ 引脚对，但链路可查 |

> LLM 不是被「杜绝」，而是**不强制依赖**——它作为可选兜底（云端 API + 记忆）挂在外面，剥离了骨架照样跑。

## 开源边界

| 开什么 | 不开什么 |
|---|---|
| 确定性骨架（编排 / 106 校验 / 编译链路） | 芯片肖像 / 功能模板 / 手册数据（护城河） |
| 契约接口（数据怎么接入） | LLM 指挥层（可选兜底，可剥离） |
| 血肉格式说明 + 空模板 | 测试脚本（无血肉，测试无意义） |
| 骨架自检脚本 | 上板验证的完整数据 |

## 快速开始

**① 骨架自检（空车能开，不依赖血肉）**

```bash
python scripts/self_check.py
```

预期输出 `5/5 通过`（契约结构 / 106 校验规则 / 核心模块 import / 接口契约 / assemble_routed 空车跑通）。

**② 跑最小示例（文字 → 完整工程）**

```bash
python examples/run_example.py
```

「点灯」→ 识别 `example_led` 模板 → 生成 18 文件完整工程（main/gpio/startup/Makefile/链接脚本全齐）。
用的是 `stm32f407zgt6` 最小肖像（真芯片名 + 点灯最小字段），完整外设需填完整肖像（见 `docs/DATA_SPEC.md`）。

**③ 一条龙（文字 → 生成 → 编译 → 烧录，需工具链 + 板子）**

```bash
python scripts/build_flash.py "点灯"              # 默认「点灯」，编译 + 烧录
python scripts/build_flash.py "点灯" --no-flash   # 只编译，不烧录
```

工具链自动探测（arm-gcc / make / STM32Cube HAL 库 / STM32_Programmer_CLI），
也可用环境变量覆盖：`AGENT_S_ARM_GCC` / `STM32_CUBE_FW` / `STM32_PROGRAMMER_CLI`。
没工具链 / 没板子也能跑「生成」这一步，编译 / 烧录会明确提示缺什么、跳过什么，不静默失败。

## 版本与更新

- **当前 `V1.0`** = 初版框架（不是功能里程碑）。
- **会更新**：确定性骨架 / 校验规则 / 生成器会持续打磨；额外工具（如串口车间 `serial_workshop`）会陆续开源。
- **不随仓库更新**：芯片肖像 / 功能模板 / 手册数据（内容护城河）——那是你的活，永远留白。

## 现状与已知边界（诚实声明）

这是 V1.0 初版框架，以下地方可能不完整 / 会卡，需要你理解并整改：

| 项 | 现状 | 说明 |
|---|---|---|
| 完整生成 | 需完整芯片肖像 | 示例只给「stm32f407 最小肖像」（仅点灯字段），完整引脚/外设是护城河，需自己填 |
| server 入口 | 依赖智能层 | `src/api/server.py` 是智能层（LLM）入口，开源仓不含智能层，需从原项目补 |
| `functional_assembler.py` | 836 行待拆分 | 已知超大文件，拆分在计划中（不影响使用） |
| 异常处理 | 有意 fail-closed | 大量 `except Exception` 是「兜底设计」非偷懒，多数带注释说明 |

> 项目是「成长性项目」：这些边界会随迭代收敛。clone 下来遇到卡点，先看 `docs/` 对应文档。

## 两条铁律（读代码前先懂）

1. **开发板与芯片是并列关系**：芯片肖像给「芯片默认引脚」，开发板给「板载定型引脚」，井水不犯河水。提到板子走板子那套，提到芯片走芯片那套。
2. **血肉 = 材料，骨架 = 编排**：代码只定义「推理框架 / 编排流程」，具体内容全由材料（JSON/YAML）驱动。加能力 = 加材料 + 新实现，不改骨架。

详见 `docs/ARCHITECTURE.md`。
